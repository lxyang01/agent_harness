# 客户反馈异常调查

## 工作流

1. 确认当前周期和等长基线周期；用户未指定时默认最近 7 天对比此前 7 天。
2. 调用 `feedback_compare` 获取总量变化，再调用 `feedback_anomalies` 定位标签或模块异常。
3. 同时检查当前量、基线量、绝对增量和增长率。基线为零时写“新出现”，不要写无限增长。
4. 排除低基数误判。只有百分比高而绝对量很小时，降级为“观察项”。
5. 使用 `feedback_search` 下钻相关范围，并通过 `feedback_samples` 获取脱敏样本验证问题表现。
6. 输出异常事实、证据范围、可能解释、待验证信息和下一步行动。

## 判断纪律

- “异常”表示相对基线发生明显变化，不等同于系统故障。
- 不使用未来数据或不等长周期进行比较。
- 数据量不足时明确标记低置信度。
- 至少引用一项统计证据；给出原因假设时还应引用样本证据。
- 不因某标签增长就断言某次发布导致问题。

## 输出结构

1. 异常摘要。
2. 数据事实表：当前量、基线量、绝对变化、变化率。
3. 样本观察。
4. 原因假设与置信度。
5. 建议的验证动作和负责人方向。

计算和解释异常时读取 [references/investigation-rules.md](references/investigation-rules.md)。需要结构化保存证据时使用 [assets/evidence-template.json](assets/evidence-template.json)。
