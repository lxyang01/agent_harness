# 账单异常调查

## 工作流

1. 确认当前周期和等长基线周期；用户未指定时默认最近 7 天对比此前 7 天。
2. 按判定口径选择下钻顺序：
   - 怀疑类别支出激增（spike）：先 `bill_compare` 确认整体与类别结构变化，再 `bill_anomalies` 的 spike 维度定位类别。
   - 怀疑重复扣费（duplicate）、订阅涨价（price_hike）或大额离群（outlier）：直接调用 `bill_anomalies` 对应维度，再用 `bill_samples` 读取脱敏样本核对具体交易。
3. 同时检查当前金额/笔数、基线值、绝对增量和变化率。基线为零时写“新出现”，不要计算百分比。
4. 低基数与小额警告：类别笔数很少或金额基数很小（例如单笔几元的订阅）时，即使变化率很高也降级为“观察项”，优先展示绝对金额。
5. 使用 `bill_search` 按商户、类别或金额区间下钻，通过 `bill_samples` 验证具体表现。
6. 输出异常事实、证据范围、可能解释（附置信度）、待验证信息和下一步行动。

## 判断纪律

- “异常”表示统计口径上的显著变化，不等同于盗刷或商户故障；是否盗刷必须由用户确认，不得直接下结论。
- 不使用未来数据或不等长周期进行比较。
- 订阅是否涨价以 `subscriptions.expected_amount` 为基准核对，不凭印象判断。
- 数据量不足时明确标记低置信度；至少引用一项统计证据，给出原因假设时还应引用样本证据。

## 输出结构

1. 异常摘要。
2. 数据事实：当前金额/笔数、基线值、绝对变化、变化率。
3. 样本观察（脱敏）。
4. 原因假设与置信度（低/中/高）。
5. 建议的验证动作。

四类异常的阈值与计算口径读取 [references/investigation-rules.md](references/investigation-rules.md)。需要结构化保存证据时使用 [assets/evidence-template.json](assets/evidence-template.json)。
