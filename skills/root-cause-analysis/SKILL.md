# 账单根因分析

## 工作流（四段式）

1. 事实：先定义待解释现象（时间范围、商户、类别、金额变化），用 `bill_overview`、`bill_compare` 或 `bill_anomalies` 建立统计事实，再用 `bill_search` 和 `bill_samples` 获取脱敏交易记录。
   - 已知商户或类别时优先传 `merchant`/`category`；全文检索只传可能出现在交易编号、商户或备注原文中的短关键词，不要把“订阅涨价”等结论名称当作检索词。
   - 用户指定“最多 N 条”时，在查询和样本工具中显式传递 `limit <= N`。
   - 查询返回 0 条时，按照工具 `retry_hint` 改用类别、商户或更短关键词重试一次；仍为空则停止推断并报告证据不足。
2. 假设：为每个原因假设列出支持证据。常见方向包括年费/按年扣费周期、家庭共享成员的消费、试用期转正自动续费、商户价格调整、套餐升档或重复扣款。
3. 反向证据：为每个假设列出矛盾证据或缺失信息；与交易记录矛盾的假设必须降低置信度或放弃。
4. 验证动作：给出能区分多个假设的动作，例如核对商户公告或收据、比对历史账单、与家人确认、联系商户客服、发起退款工单。

## 强制区分

- 数据事实：工具结果直接支持的金额、笔数、分布、变化和样本内容。
- 分析观察：从多条证据归纳出的共同表现。
- 原因假设：尚未被商户公告、账单明细或复现证据确认的解释。
- 已确认根因：具有直接、可重复且排除主要替代解释的证据。

未经证实禁止写“已确认根因”；只能写“最可能的假设是……（置信度：低/中/高）”。完成结论前使用 [references/causality-checklist.md](references/causality-checklist.md) 自检。
