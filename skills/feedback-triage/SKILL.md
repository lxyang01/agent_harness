# 客户反馈分流

## 工作流

1. 明确分析范围。优先从用户问题提取时间、模块、客户等级、状态、标签和关键词；没有明确范围时使用全量概览并说明范围。
2. 调用 `feedback_overview` 获取总体事实。不要在查询前猜测数量、比例或排名。
3. 根据问题决定是否调用 `feedback_search` 定位明细，或调用 `feedback_samples` 获取最多 20 条脱敏样本。
4. 把输出拆成“数据事实”“初步判断”“下一步建议”。初步判断必须标明证据范围。
5. 数据为空时停止推断，说明使用的筛选条件并建议用户调整范围。

## 分流规则

- 用户只问整体情况：概览即可，不为增加步骤而读取样本。
- 用户问某类问题的具体表现：先概览或检索，再读取代表性样本。
- 用户问变化、激增或趋势：转入 `anomaly-investigation`。
- 用户问原因：收集事实和样本后转入 `root-cause-analysis`。
- 用户要求正式汇报：分析完成后转入 `executive-report`。

## 输出要求

- 写明分析范围和样本数量。
- 数字只引用工具结果。
- 不展示未脱敏的个人信息。
- 不把单条反馈当作总体结论。
- 建议必须能对应到已展示的问题或证据。

需要解释标签含义或分流边界时，读取 [references/taxonomy.md](references/taxonomy.md)。
